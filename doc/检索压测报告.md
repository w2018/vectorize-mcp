# 记忆检索压测报告（v0.3.1）

## 目的
验证「记忆检索」在较大数据量与全类型覆盖下的召回质量，并据结果优化排序算法。

## 数据集
- 生成脚本：`tmp/bench-search.ts`（离线基准）、`tmp/seed-offline.ts` + `tmp/finish-bench.mjs`（线上演示账户）。
- 规模：340 条构造记忆，覆盖全部 10 类：fact / preference / profile / project / decision / lesson / task / person / concept / persona。
- 每条记忆 1–2 条验证查询，含自然语言提问（如「登录模块的负责人是谁」「登录模块为什么选 TypeScript」）。
- 线上演示账户：**检索测试-全类型(可删除)**（QQBOT 账户，约 300 条，全部类型），可直接在 Web 账户列表选择、测试后删除。

## 优化前后（离线全量 660 条查询）
| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| hit@1 | 6.7% | 58.9% |
| hit@3 | 20.9% | 82.9% |
| hit@5 | 20.9% | 82.9% |
| MRR | 0.124 | 0.699 |
| 未命中率 | 79.1% | 17.1% |

各类型 hit@5（优化后）：fact 100%、preference 98%、project 100%、decision 100%、lesson 100%、task 100%、concept 75%、person 75%、persona 45%、profile 0%（该批 profile 查询未含具体岗位词，属数据集歧义）。

## 线上抽样（195 条查询，经真实 MCP 服务）
- hit@1 = 67.7%，hit@3 = 87.2%，MRR = 0.771，未命中率 12.8%。
- fact / project / task / lesson / decision 均 100%，preference 96%，persona 45%。

## 优化内容
1. **IDF 词频逆文档加权**：检索词权重 = log(1 + N/(1+df))，高频通用词权重自动降低。
2. **字段加权**：命中标题 ×1.4、命中关键词 ×1.4，正文 ×1。
3. **排序改为相关度优先**：rank = 0.7×relevance + 0.3×weight，避免高重要度弱相关记忆压过精确命中。
4. **口语同义词扩展**：原因/为什么→因为；坑/教训→经验、避免；没做→待办；进展/进度→阶段；选型→采用；岗位/职业→负责；喜欢→偏好；不喜欢→避免。

## 结论与剩余限制
- 检索质量已从「基本搜不到」提升到可用水平；主要剩余失败来自**数据集本身歧义**（同一主题被 7 类记忆共享，或同一人物/人设名称重复），不是排序缺陷。
- 未配置向量编码器时仍是纯词法检索；配置 embeddingModel / embeddingBaseUrl / embeddingDimension 后可进一步提升语义召回。
- 建议后续用真实使用数据持续观察「空结果率 / 词法降级率 / 索引失败」，按周复核。
